# wrapper-manager on Cloudflare

Runs [wrapper-manager](../manager/) for amdl on Cloudflare Containers, behind a
static key. It needs a Workers Paid plan.

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/AMDL-Web/wrapper/tree/amdl/cloudflare)

## Set up

1. In amdl, click **Generate** next to the wrapper key field (Settings →
   wrapper); the key is copied.
2. Click the Deploy button above and paste it into `API_KEY` (a password
   manager may fill that field with a password: check it). The deploy
   copies this directory into a new GitHub repository, creates the Worker,
   its Durable Object and the R2 bucket, and builds the container image.
   The first container then takes about ten minutes to be placed; until it
   is, requests get 503 and the logs say there is no container instance.
3. After the deploy, put the Worker's URL and the same key into amdl.
4. Log in your Apple Music accounts from amdl as usual (up to 10), or from
   the panel at the Worker's URL, which asks for the same key.

From mainland China, `*.workers.dev` is unreachable (its DNS answers are
poisoned and its TLS connections reset), so add a custom domain to the Worker
(Settings → Domains & Routes) and give amdl that URL instead.

Every amdl instance uses the same key; several devices share it. To rotate:
`wrangler secret put API_KEY` (or Settings → Variables and Secrets in the
dashboard), then update the key in amdl.

## How it works

- **Key.** Every path needs `Authorization: Bearer <API_KEY>`. The Worker
  compares digests in constant time and answers 401 without waking the
  container. While `API_KEY` is unset or shorter than 32 characters, every
  request gets 503 instead. Nothing key-shaped is stored; the secret lives
  only in the Worker's environment.
- **Panel.** `/` is the manager's panel, which needs no key to open: it
  shows a field for the key and nothing else until the key is right, as
  everything it shows comes from the API. Its files come from the manager
  and are kept by the Worker, so opening it doesn't wake the container. Set
  the variable `PANEL` to `off` to leave it out: `/` answers 404.
- **Container.** One `basic` container (1/4 vCPU, 1 GiB) runs wrapper-manager
  with `-launcher root`. It sleeps after five idle minutes, and its disk does
  not survive that.
- **Backup.** `instances.json` and every account's data directory are kept in
  R2 as one AES-256-GCM encrypted object. The key is generated by the Worker
  and kept in the Durable Object. The backup is written after a login or
  logout, after the daily renewal and before the container sleeps, and is
  restored into a freshly started container before any request reaches it.
- **Answers while asleep.** `/status` and `/token` (per `instance` or
  `region`) are answered from the last answer while the container sleeps, and
  reused for 30 s and 60 s while it runs. `/key`, `/m3u8`, `/lyrics`,
  `/webplayback`, `/license`, `/login`, `/logout` and `/check` wake it; a cold start
  takes a few seconds plus the accounts' start-up.
- **Renewal.** A daily Cron Trigger wakes the container. wrapper-lite
  refreshes a music token older than its refresh interval a few seconds after
  it starts; the Worker waits for each account's new token, caches it and
  backs it up.

Cloudflare runs the container and holds the backup key, so it can reach the
accounts' sessions in principle. Keep that in mind against running the
manager on your own machine.

## Sizing

Each account runs its own wrapper-lite. Measured on `basic` with two accounts,
each account's wrapper-lite used about 56 MiB right after start and 69 MiB
after decrypting eleven tracks. At those numbers the
manager's cap of 10 accounts fits in `basic` (1 GiB) with little headroom;
`standard-1` (1/2 vCPU, 4 GiB, `instance_type` in `wrangler.jsonc`) leaves
plenty.

## Updating

The image builds the manager at `WRAPPER_COMMIT` in the `Dockerfile` and
installs the wrapper-lite release that manager pins, checked against its
sha256. A template change that needs a newer manager, or a newer wrapper-lite,
bumps `WRAPPER_COMMIT` in the same commit. `LITE_PAYLOAD_URL` installs another
payload zip instead.
